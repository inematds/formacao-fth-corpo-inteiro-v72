Aula 3 · 15 min

Retargeting: do esqueleto humano ao robô

Uma pessoa tem 1,70 m, ombros largos e juntas que o robô não tem; o G1 tem 1,32 m e 29 motores com limites. Retargeting é a conta que transforma um no outro, quadro a quadro, sem quebrar nenhum limite. Nesta aula você instala o GMR num ambiente próprio, leva 10 s de boxe para o G1 e confere cada quadro contra os limites das juntas.

Começar a aula

Nesta aula você vai

  1. 1O que o retargeting resolve: escala, juntas diferentes e limites
  2. 2Um ambiente por ferramenta: o .venv-gmr com versões fixadas
  3. 3IK por quadro com o mink: pontos do humano viram alvos do robô
  4. 4Por que o limite depende do arquivo do robô

Objetivo: levar um clipe humano para o G1 com o GMR num ambiente próprio e conferir que nenhum quadro passa do limite das juntas.

02 · Por que um ambiente só para o GMR

Clique em cada ponto.

1. torch

O pacote do GMR importa o PyTorch logo ao ser carregado (o modelo cinemático usa tensores), mesmo para retargeting de BVH. Pôr torch no .venv das práticas de MuJoCo deixaria o ambiente pesado à toa.

Solução: um .venv-gmr só para ele, com o torch de CPU do índice oficial do PyTorch.

2. setup.py

No commit bb1bbe4 (02/04/2026), o setup.py pede proxqp, smplx e redis, mas o retargeting de BVH usa o solver daqp (padrão no código) e não precisa dos outros.

Quando código e lista de dependências divergem, vale o código: o curso instala o GMR com --no-deps e fixa à mão só o que roda.

Regra da formaçãoUm ambiente por ferramenta e versões fixadas por projeto. O BeyondMimic fixa o Isaac Lab 2.1.0; o mjlab usa o MuJoCo Warp com uv; num ambiente só, um quebra o outro.

3. Limites

O modelo do G1 que o GMR usa (g1_mocap_29dof.xml) tem a mesma ordem de juntas do Menagerie, mas limites mais apertados em 15 das 29 juntas (medido em 19/10/2026).

Como o retargeting respeita os limites do GMR, o resultado cabe nos do Menagerie. O contrário não valeria: confira sempre no modelo que vai executar.

03 · Instalar o GMR no .venv-gmr

Acrescenta ao clone do GMR só o código e o modelo do G1 (sparse-checkout add), cria o segundo ambiente e fixa as versões testadas. Primeira vez: o torch de CPU tem algumas centenas de MB.

Terminal · ambiente do GMR
F=${FTH:-$HOME/fth}; cd $F/GMR
git sparse-checkout add general_motion_retargeting scripts assets/unitree_g1
cd $F && [ -d .venv-gmr ] || python3.12 -m venv .venv-gmr
. .venv-gmr/bin/activate
pip install -q --index-url https://download.pytorch.org/whl/cpu torch==2.14.1
pip install -q mujoco==3.16.0 numpy==2.5.4 scipy==1.18.1 mink==1.3.0 qpsolvers==4.13.0 daqp==0.10.3 rich tqdm loop_rate_limiters imageio
pip install -q --no-deps -e GMR
python3 -c "from importlib.metadata import version as v; print(*[f'{p} {v(p)}' for p in ('torch', 'mink', 'mujoco', 'general_motion_retargeting')], sep=' · ')"
Exemplo do repositório

O retarget.py lê o BVH como o script do GMR para Xsens faz (sem a interface gráfica dele), chama o GMR quadro a quadro e confere cada quadro nos limites do G1 do Menagerie.

F=${FTH:-$HOME/fth}; cd $F/corpo-inteiro && . $F/.venv-gmr/bin/activate
