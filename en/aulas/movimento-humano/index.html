Lesson 2 · 15 min

Human motion as data

2026 whole-body policies learn from hours of human motion. Before using that data, you need to know how to read it and whether you are allowed to use it. In this lesson you open a BVH clip, count frames, fps and joints, write a clip of your own, and understand why the course does not redistribute any public dataset.

Start the lesson

In this lesson you will

  1. 1Where human motion comes from: mocap, video and VR
  2. 2The BVH format inside: a skeleton and one line per frame
  3. 3AMASS, LAFAN1 and the license question
  4. 4How to catch a truncated clip before it ruins the retargeting

Goal: read a motion capture clip (BVH) and report frames, fps and joints, knowing where the data comes from and under what license.

02 · The datasets you will run into

Click each one.

1. AMASS

A collection of many captures converted to the same parametric body (SMPL-X). It is the most common input for GMR and for several motion tracking works.

Requires registration on the site. The terms for an open course were not checked: read them before using it and before publishing anything derived from it.

2. LAFAN1

An animation dataset in BVH used in many retargeting examples (GMR has a ready-made configuration for it).

Same license caveat: not confirmed by the training's research on 10/19/2026.

3. Your data

The cleanest path for a course, a product or an article: capture your own motion (inertial suit, cameras, VR) or generate a synthetic clip.

The kit's bvh_minimo.py writes a BVH from scratch: a 5-joint skeleton and a wave. It is not a real human, but it shows the format and the license is yours.

ReportedThe README of GR00T-WholeBodyControl cites the BONES-SEED dataset (03/16/2026, more than 142 thousand motions, about 288 h, with G1 trajectories in MuJoCo). The license was not checked: read it before using it.

03 · Download only the GMR test clip and read it

The GMR repository has 1.2 GB in the assets folder, because of the robot meshes. The sparse-checkout downloads only the clip's folder, 2.9 MB (measured on 10/19/2026, commit bb1bbe4). ler_clipe.py uses no extra library: it reads the BVH text.

Terminal · GMR clip
F=${FTH:-$HOME/fth}; cd $F
[ -d GMR ] || git clone -q --filter=blob:none --sparse https://github.com/YanjieZe/GMR
cd GMR && git sparse-checkout set assets/xsens_bvh_test
git checkout -q bb1bbe4 && git log -1 --format='GMR %h (%ad)' --date=short
cd $F/corpo-inteiro && . $F/.venv/bin/activate
python3 kit/ler_clipe.py $F/GMR/assets/xsens_bvh_test/251021_04_boxing_120Hz_cm_3DsMax.bvh; echo "saída: $?"

04 · A BVH of your own, made from scratch

Five joints (hips, spine, head, right arm and right forearm), 60 frames at 30 Hz: the arm rises in 0.5 s and the forearm waves.

Terminal · generate and read aceno.bvh
F=${FTH:-$HOME/fth}; cd $F/corpo-inteiro && . $F/.venv/bin/activate
python3 kit/bvh_minimo.py && python3 kit/ler_clipe.py $F/movimentos/aceno.bvh; echo "saída: $?"
Example from the repository
gravado: ~/fth/movimentos/aceno.bvh (60 quadros a 30 Hz)

3 channels per joint + 3 for the root position = 18. The same reading works for any BVH.

05 · Practice

Read it, check it, and decide whether you can use it.

5 min

E3 · License sheet

10 min

For a clip you want to use (AMASS, LAFAN1 or another), write three lines in ~/fth/movimentos/licenca.md: Fonte, Licença (with the link) and Pode redistribuir.

Done when: grep -c -E "^(Fonte|Licença|Pode redistribuir):" ~/fth/movimentos/licenca.md → 3.

07 · In three sentences

FormatBVH = skeleton + one frame per line; frames, fps and channels come from the text.
LicenseWithout clear terms, don't redistribute: use your own data or data that ships with a license.
IntegrityCheck frames × lines before any retargeting.
