Lesson 5 · 15 min

Whole-body teleoperation

Teleoperation is the fastest way for a humanoid to do a new task and to collect demonstrations for a VLA. The operator moves their arms in a VR headset and the robot repeats them; delay is what ruins it. In this lesson you teleoperate both of the G1's arms with a script and measure the latency at which everything falls apart.

Start the lesson

In this lesson you will

  1. 1The path of a gesture: VR, network, whole-body control, joint
  2. 2Latency × reference horizon: don't confuse it with SONIC's 80 ms
  3. 3Arm reach: the target that no latency can save
  4. 4Teleop as data collection for VLA (TWIST2, GR00T-WBC)

Goal: teleoperate both of the G1's arms through a script of targets with latency and measure how many targets the hand reaches.

02 · Three things the 2026 research makes clear

Click each one.

1. 80 ms

SONIC has a "low latency" checkpoint (06/16/2026) that looks 4 future frames ahead at 20 ms: about 80 ms of reference horizon. The default checkpoint looks 10 frames ahead (about 200 ms).

The README itself warns: these numbers are not the total teleoperation latency, which includes sensor, network, preprocessing and inference.

2. VR ready

The GR00T-WholeBodyControl repository ships VR teleop with PICO, CloudXR inside the process via isaacteleop[cloudxr] (06/16/2026) and IsaacTeleop 1.4 with Jetson AGX Orin (09/14/2026).

On 05/07/2026 it gained the end-to-end VLA flow on the G1: collect with teleop, fine-tune GR00T N1.7 and deploy with SONIC.

3. One policy

HOVER (ICRA 2025, reported) distilled several command modes (VR, mocap, exoskeleton, joystick) into one policy of about 1.5M parameters.

SONIC uses a single token space for VR, human video and VLA: the same controller obeys any of them (lesson 7).

03 · Teleoperate both arms from a script

The kit/passos.json script plays the operator's role: six controller offsets, alternating hands. The sixth, on purpose, asks for 60 cm forward.

Terminal · teleop with 80 ms
F=${FTH:-$HOME/fth}; cd $F/corpo-inteiro && . $F/.venv/bin/activate
python3 kit/teleop_sim.py --roteiro kit/passos.json; echo "saída: $?"

ERRO no roteiro: mão 'esquerdo' (use direita ou esquerda)
saída: 1

The script accepts only "direita" and "esquerda". A typo stops before touching the robot, not in the middle of a session.

alvos atingidos: 6/6

The 6th target with dx 0.25 instead of 0.60: all reached.

04 · Where the delay breaks things

The same script with five latencies. Each target's window is 0.6 s.

Terminal · sweep the latency
F=${FTH:-$HOME/fth}; cd $F/corpo-inteiro && . $F/.venv/bin/activate
for ms in 0 80 300 450 550; do
  echo "$ms ms → $(python3 kit/teleop_sim.py --roteiro kit/passos.json --latencia-ms $ms | tail -1)"
done
Example from the repository
0 ms → alvos atingidos: 5/6
80 ms → alvos atingidos: 5/6
300 ms → alvos atingidos: 5/6
450 ms → alvos atingidos: 4/6
550 ms → alvos atingidos: 0/6

Up to 300 ms there is window to spare. At 450 ms one target already misses the window; at 550 ms none is reached in time. With a real operator, the effect shows up sooner: they start correcting for the delay.
