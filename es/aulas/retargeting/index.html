Clase 3 · 15 min

Retargeting: del esqueleto humano al robot

Una persona mide 1,70 m y tiene articulaciones que el robot no tiene; el G1 mide 1,32 m y, en el modelo de Menagerie, tiene 29 articulaciones con límites. El retargeting es la cuenta que lleva de uno a otro, cuadro a cuadro. En esta clase instalas GMR en un entorno propio, llevas 10 s de boxeo al G1 y verificas cada cuadro contra los límites de las articulaciones.

Comenzar la clase

En esta clase vas a

  1. 1Lo que resuelve el retargeting: escala, articulaciones distintas y límites
  2. 2Un entorno por herramienta: el .venv-gmr con versiones fijadas
  3. 3IK por cuadro con mink: los puntos del humano se vuelven objetivos del robot
  4. 4Por qué el límite depende del archivo del robot

Objetivo: llevar un clip humano al G1 con GMR en un entorno propio y comprobar que ningún cuadro pasa del límite de las articulaciones.

02 · Por qué un entorno solo para GMR

Haz clic en cada punto.

1. torch

El paquete de GMR importa PyTorch apenas se carga (el modelo cinemático usa tensores), incluso para retargeting de BVH. Poner torch en el .venv de las prácticas de MuJoCo volvería el entorno pesado sin necesidad.

Solución: un .venv-gmr solo para él, con el torch de CPU del índice oficial de PyTorch.

2. setup.py

En el commit bb1bbe4 (02/04/2026), el setup.py pide, entre otros, proxqp, smplx y redis, pero el retargeting de BVH usa el solver daqp (predeterminado en el código) y no necesita los demás.

Cuando el código y la lista de dependencias no coinciden, vale el código: el curso instala el GMR con --no-deps y fija a mano solo lo que se ejecuta.

Regla de la formaciónUn ambiente por herramienta y versiones fijadas por proyecto. BeyondMimic fija Isaac Lab 2.1.0; mjlab usa MuJoCo Warp con uv; en un solo ambiente, uno rompe al otro.

3. Límites

El modelo del G1 que usa el GMR (g1_mocap_29dof.xml) tiene el mismo orden de articulaciones que Menagerie, pero límites más estrechos en 15 de las 29 articulaciones (medido el 19/10/2026).

Como el retargeting respeta los límites del GMR, el resultado cabe en los de Menagerie. Lo contrario no valdría: comprueba siempre en el modelo que vas a ejecutar.

03 · Instalar el GMR en el .venv-gmr

Agrega al clon de GMR solo el código y el modelo del G1 (sparse-checkout add), crea el segundo entorno y fija las versiones probadas. Primera vez: el entorno completo ocupó 1,2 GB en una mesa de trabajo nueva, casi todo del torch de CPU (medido el 19/10/2026).

Terminal · ambiente del GMR
F=${FTH:-$HOME/fth}; cd $F/GMR
git sparse-checkout add general_motion_retargeting scripts assets/unitree_g1
cd $F && [ -d .venv-gmr ] || python3.12 -m venv .venv-gmr
. .venv-gmr/bin/activate
pip install -q --index-url https://download.pytorch.org/whl/cpu torch==2.14.1
pip install -q mujoco==3.16.0 numpy==2.5.4 scipy==1.18.1 mink==1.3.0 qpsolvers==4.13.0 daqp==0.10.3 rich tqdm loop_rate_limiters imageio
pip install -q --no-deps -e GMR
python3 -c "from importlib.metadata import version as v; print(*[f'{p} {v(p)}' for p in ('torch', 'mink', 'mujoco', 'general_motion_retargeting')], sep=' · ')"
